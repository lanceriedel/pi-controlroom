The strip shows `✓ acceptance` / `✗ acceptance (N)` per worker once a result exists (tick caches `check` by result mtime in `logs/.health.json`). ## Launch-prompt text (exact)
`$PRE` = `Read docs/briefs/memory/LESSONS.md first (project lessons; treat as rules). Then read` (or `Read` when memory/ is absent); `$NUM` = the brief's 3-digit number; `$CTL` = `logs/.controller`.

> $PRE $BRIEF and execute it end to end. Work autonomously; do not ask questions unless truly blocked. Save deliverables where the brief specifies and write the final summary to docs/briefs/results/ as the brief says; that result file must contain a `## Deviations` section (what you did differently from the brief and why, or `none`) and end with the line `DONE $NUM`, and you may only create or modify paths the brief's `writes:` line allows (plus your result file and logs/) — `controlroom check $NUM` is run against it before the work lands. Save partial results early and often. After any compaction or context reset, re-read your brief before continuing. When done, reply with the single line: DONE $NAME — in your own pane only; never type into another pane or tab (this room's controller is pane $CTL · `herdr agent prompt $CTL …` only if the brief says so; CONTROLLER tabs in other workspaces are other rooms).

## Deviations
- **Implicit write-scope allow-list is wider than the brief's** (`logs/**` + result path): also `docs/briefs/STATUS.md`, `docs/briefs/AUTOMATIONS.md`, `docs/briefs/memory/**`, `docs/status/**`. Reason: the controller rewrites the board and the tick rewrites the ledger while a worker runs, briefs ask workers to record `decide|lesson` lines, and `launch`/`land` regenerate the status page — without these every worker would fail write-scope on the controller's edits. `read-only:` still protects any of them explicitly (S5).
- **Steer ACK pane read uses `--lines 200`, not 80** — a busy worker scrolls more than 80 lines between ticks; 200 matches `verify`'s window. The regex anchors a whole line (`^[\s●•>*-]*ACK S###\s*$`) so the pasted instruction text ("reply ACK S001 on its own line…") can't match itself.
- **Steering a `done` agent still delivers the prompt** (plus the `steer after DONE` log line and a ⚠ on stdout) — warm idle workers taking follow-ups is a documented pattern; the point of the brief was that it must never be silent, and it isn't.
- **`land` on a row whose brief file is missing (`check` rc 2) lands as before** — pre-018 rows and `dream` rows have no brief under `docs/briefs/NNN-*.md`; refusing them would block every old board.
- **`check` output has a third state, `SKIP`** (write-scope with no `writes:` header) rather than silently passing — one line more than the brief's `PASS|FAIL`, never affects the exit code.
- No `--help` arm was added to `land` (the brief didn't ask; `--force` is filtered from the agent/brief filter set).
- Toast dedupe for `land` keys on the board state (`done — acceptance failed` already present) rather than a log grep — simpler, and it re-toasts correctly after a worker fixes and then breaks the result again.

## Still open
- **Write-scope is repo-global**: two workers in one repo at once will flag each other's uncommitted paths (and the controller's un-committed edits outside the implied set). Options for 019+: scope by `git diff --name-only <launch-commit>` recorded at launch, or per-worker worktrees. Recorded as L048.
- `steer` targets local agents only (no `<machine>/<agent>` form yet; `verify`/`resume` have it since 015).
- `check` does not verify the acceptance block's commands themselves are safe — a brief author could put `rm -rf` in it. Briefs are controller-written, so same trust boundary as the brief text; worth a `--dry-run` listing in 019 if judges start writing checks.
- The strip's `✓/✗ acceptance` only appears for agents the board names (cache keyed by board agent); a worker launched without a board row has no entry until the controller adds it.
- `land --force` prints `landed … (done — acceptance failed …)` as the state — truthful but noisy; could read `(forced)`.
- `cr_has_section` matches heading **prefix** (`"## Proof"` matches `## Proof (write as you go)`), which also means `"## Dev"` would match `## Deviations` — fine for the intended vocabulary, document if it bites.
